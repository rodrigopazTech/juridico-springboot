# Matriz de Implementación V2

Fecha: 9 de septiembre de 2026

## Criterio de clasificación

| Clasificación | Criterio |
|---|---|
| Obligatorio para la migración V1 | Evita pérdida, alteración, duplicidad o vinculación incorrecta; permite reintentar y conciliar; o evita que un registro migrado quede inutilizable en la operación actual. |
| Recomendado para V1 | Mejora calidad o atención posterior, pero puede operar temporalmente con una regla documentada y control manual. Se vuelve obligatorio si el supuesto indicado forma parte del lote real. |
| Postergable para V2 o V3 | Introduce normalización, automatización o capacidades nuevas que no son necesarias para cargar de forma íntegra los datos ya soportados. |

La clasificación se refiere a la primera migración productiva. “Obligatorio” no significa que el Excel por sí solo resuelva el cambio: el backend, la base de datos y el proceso de aceptación deben implementar el mismo contrato.

## 4. Dependencias entre cambios

| Secuencia | Cambios | Resultado esperado |
|---|---|---|
| 1 | O01–O03 | Existe una sola plantilla V1 reconocible y descargable. |
| 2 | O04–O08 | Claves y catálogos se resuelven sin coincidencias parciales. |
| 3 | O09–O12 | Los datos se transforman al modelo actual sin alterar hechos históricos ni dejar registros inutilizables. |
| 4 | O13–O18 | El lote se previsualiza, aplica, reintenta y concilia con trazabilidad. |
| 5 | O19 | La operación inicia después de aceptar datos y asignar pendientes. |
| 6 | R01–R10 | Se reducen pendientes manuales y se mejora la continuidad operativa. |
| 7 | P01–P10 | Se incorporan capacidades nuevas sin bloquear la primera migración. |

## 5. Criterio de salida para la migración V1

La migración puede autorizarse cuando O01–O19 estén implementados o exista una exclusión de alcance explícita para O16/O17 si no se migrará ningún documento. R02 se vuelve obligatorio si el lote contiene usuarios con varias gerencias o materias que no puedan representarse sin pérdida. R05 se vuelve obligatorio si se migrarán varios documentos por audiencia o término.

Las pruebas mínimas deben demostrar: más de 200 filas; claves repetidas; reintento completo; número de expediente homónimo; catálogo inexistente; usuario sin correo; término vencido abierto; audiencia histórica concluida; archivo faltante; y conciliación exacta entre filas recibidas y resultados persistidos.
